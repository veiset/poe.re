# https://poe.re  ·  https://poe2.re

This is a single monorepo hosting two separate sites:

- **poe.re** — Path of Exile 1 regex tool
- **poe2.re** — Path of Exile 2 regex tool

The `poe/` and `poe2/` directories are independent Vite apps. Reusable
components, utilities, core helpers, styles and types live in `shared/`.
Game-specific generated data stays with its app. Each app builds to its own
output and deploys to its own domain.

## Path of Exile 1  (poe.re)

A tool for generating vendor search strings. With no false positives matches and with query shortening, so you can fit more stuff in to your search!

![preview](poe/public/preview.png)

### Supported pages

- Items (inc. flasks and jewels)

## Development Setup

This project uses [pnpm](https://pnpm.io/) and [Vite](https://vitejs.dev/).

```bash
# Clone the repo
git clone git@github.com:veiset/poe.re.git
cd poe.re

# Install dependencies
pnpm install

# Develop poe.re (Path of Exile 1)
pnpm dev

# Develop poe2.re (Path of Exile 2)
pnpm dev:poe2

# Run tests
pnpm test

# Type-check
pnpm typecheck

# Build BOTH apps -> dist/poe and dist/poe2
pnpm build

# Build a single app
pnpm build:poe      # -> dist/poe
pnpm build:poe2     # -> dist/poe2
```

## Cross-domain links

The two apps link to each other externally. Override the target domains with
env vars if you run a staging setup:

```env
VITE_POE1_URL=https://poe.re
VITE_POE2_URL=https://poe2.re
```

## Generated data

Mods, items, gems, maps, waystones, tablets and relics are generated by
[poe-item-gen](https://github.com/veiset/poe-item-gen), which uploads them to R2 at
https://data.poe.re. Both apps load them from there in the browser: `current.json` names each
game's latest upload (`history.json` also lists the earlier ones), and its files are read from
`generated/<game>/<patch>/`. A new upload is used on the next page load, without a deploy.

The data's TypeScript types are in `shared/typedefs`, copied from poe-item-gen's latest types on
R2 (`typedefs/`). To update them, run:

```bash
pnpm fetch-typedefs
```

It downloads the files listed in https://data.poe.re/typedefs/SHA256SUMS and removes the ones R2
no longer has. Commit the result with the code that needs it.

The copies in `<app>/public/generated` are still deployed with the app. To read them instead of
R2, change `dataSource` in `shared/generatedData.ts` to `"local"`.

`GeneratedDataProvider` (`shared/components/GeneratedData/`) is the first thing each app renders
(`index.tsx`). It finds the data (`current.json`), runs the profile migrations, and then renders the
app, so everything after it can count on the patch; `useGeneratedData()` gives it to components.
When the data can't be found, it shows an error instead. `GeneratedDataFileError`, above the pages
in the layouts, says when a single file fails to load.

The bucket's CORS policy allows https://poe.re, https://poe2.re, the Cloudflare Pages
deployments (`https://*.poe-production.pages.dev`, `https://*.poe2-production.pages.dev`) and
`http://localhost` on any port. It's set with wrangler (`wrangler r2 bucket cors list
poere-generated`). Set `VITE_DATA_URL` to read the files from somewhere else.

## Trade stat mappings

Trade search buttons rely on mappings from mod ids to the official trade APIs' stat ids.
poe-item-gen generates them with the rest of the data, and the apps load them from R2 like the
other generated files: `trade-ids/Generated.TradeIds.Map.min.json` (PoE1), and
`trade-ids/Generated.TradeIds.Waystone.min.json` and `Generated.TradeIds.Tablet.min.json` (PoE2).

The old copies in `poe/src/generated/mapmods/trade/` and `poe2/public/generated/trade/` aren't used
anymore. Other projects still read them, so they stay for a while.

## Deployment (Cloudflare)

The apps deploy through **Cloudflare Pages native Git integration**, one Pages
project per domain. Deployment does not use GitHub Actions. A scheduled
Cloudflare Worker refreshes economy and league data into a public R2 bucket
every hour.

### Cloudflare Pages projects

| Project | Build command | Publish directory | Domain |
|---------|---------------|-------------------|--------|
| poe-re  | `pnpm build:poe`  | `dist/poe`  | poe.re   |
| poe2-re | `pnpm build:poe2` | `dist/poe2` | poe2.re  |

Configure both Pages projects against this repository with the build commands
and publish directories above. Set `VITE_POE1_URL`, `VITE_POE2_URL`, and
`VITE_ECONOMY_URL` in each Pages project's environment when overriding the
defaults.

### Cloudflare Workers

Deploy the scheduled economy refresher:

```bash
cd workers/economy-fetcher && npm run deploy
```

The worker writes the filtered PoE1 and PoE2 league lists to `leagues.txt` and
`poe2-leagues.txt` in the R2 bucket. The frontend reads those files through
the CDN-backed `VITE_ECONOMY_URL` endpoint.

### Advertising

Ads on **poe.re** and **poe2.re** are served by NitroPay; the code lives in
`shared/components/ads/`, `shared/core/nitroAds*` and each app's `index.html`
(the site script) and page header (the placement). See the
[privacy page](https://poe.re/privacy) for what is collected and by whom.

### Economy storage

The R2 bucket, `economy.poe.re` custom domain, CORS policy, and CDN cache rule
are managed in [`infra/cloudflare/`](infra/cloudflare/README.md).
